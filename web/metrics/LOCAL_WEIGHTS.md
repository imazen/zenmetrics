# Local learned metrics

CKDN and HyperIQA run on CPU WebAssembly after you select a qualified ONNX
export and accept that model's weight terms. The `nn-local` catalog status
means a runnable scalar route with a required local file; these models have
no browser spatial map. No restricted checkpoint is hosted by the viewer.

Choose the metric, select the file named in the panel, accept its linked
terms, and choose **Load local export**. The viewer checks the file size and
SHA-256 against [nn-models.json](nn-models.json). A different export is refused.
Selected weights stay in memory, outside Cache Storage, and are never uploaded.
Replacing a worker reloads the selected file with the consent already given on
this page. Reopening the page requires selecting the export and accepting its
terms again. Consent for one model never enables another model.

CKDN preserves its asymmetric transform: nearest-neighbor reference resize,
antialiased bicubic distorted resize, short side 329, center crop 288.
HyperIQA uses the native port's deterministic 25-crop grid and reports both
image scores. This is distinct from upstream random-crop sampling. Each
result names the CPU provider. WebGPU requests for these local routes are
refused until separately qualified. MUSIQ retains its CPU WASM default.

The runtime requires WebAssembly JSPI. A browser lacking `Suspending` or
`promising` receives an explicit learned-metric error; the ordinary CPU WASM
metrics are still usable.

Sources and terms: [CKDN card](../../crates/zenmetrics-nn/models/ckdn/card.toml),
[HyperIQA card](../../crates/zenmetrics-nn/models/hyperiqa/card.toml).
The ONNX exports come from those cards' exporters. Only the exact graph
identities listed in the browser manifest are qualified.

The [local qualification script](../../scripts/checkpoint/check-local-weights.py)
accepts a site, private model directory, native-oracle JSON and report path.
It supplies files through Chromium's file picker without serving the model
directory. It checks both fixture pairs against the native rten engine at
the existing 0.001 JND gate, exact repeat scores, absent consent, wrong size,
wrong hash, consent after loading, the UI flow, zero ONNX network requests
and the missing-JSPI error. The native fixture scores are generated by
[the oracle](../../crates/zenmetrics-browser/examples/nn_oracle.rs) with
`ZENMETRICS_NN_ACCEPT_WEIGHTS=ckdn,hyperiqa` and model names `ckdn hyperiqa`.

[Qualification receipt](local-weights-validation.json), 2026-10-18: maximum
browser/native residuals were 5.648658526856579e-6 JND for CKDN and
1.7099456654144e-6 JND for HyperIQA. Both pass the unchanged 0.001 JND gate.
The receipt retains input graph identities, source hashes, native/browser
scores and control outcomes. Cross-model consent and replacement-worker
reloading also pass. This establishes these two fixed pairs, not all image
sizes or a WebGPU route.

Baseline: `82eb7e9d`. Changes: `75fd6112`, `cad8d217`, `ea799de5`,
`8d718760`. Only `crates/vif` was edited.

Host `r7900x`, Rust 1.99.0 / LLVM 23.1.1, release with thin LTO,
`parallel` enabled, **AVX2 on both binaries**. No target-cpu override.
Each example ran three calls at 3355×2516. Single-thread uses

Cycles include process setup and input generation. Parallel cycles aggregate
all threads, so compare before/after within the same row. Shared host load
varied: these are measured examples, not production latency guarantees.
The existing vifvec example uses a synthetic offset pair with a score near
one and values exceeding 255; this does not establish natural-image quality
or performance coverage. Existing Octave goldens remain the accuracy gate.

An earlier final matrix accidentally used an AVX-512 optimized binary because
`cargo test --release --features ...avx512` rebuilt examples. That matrix is
excluded above. Preserve benchmark binaries in separate directories immediately
after each build; tests can overwrite `target/release/examples/`.

## What changed

- Vifvec correlation vectorizes independent output pixels, keeps ky/kx tap
  order, and handles reflected borders separately. The three production
  kernel shapes expose constant tap counts and sampling strides to LLVM.
- The vector-GSM covariance is factored once per band. Each block applies
  recorded pivots and triangular solves with the original operation order.
- Local window statistics vectorize independent 3×3 block centers; the five
  sums and channel masking preserve their original order.
- VIFp fuses its five horizontal statistics and consumes row rings directly
  in the vertical/GSM pass. It retains two information-term maps for the
  original raster-order logarithmic pooling, replacing three product planes
  and five full statistics maps. Inter-scale filtering also uses row rings.

VIFp `/usr/bin/time -v` maximum RSS: **965,904 → 514,072 KiB**, single-thread,
three calls at the measured size. Corresponding run-heavy receipts:

```text
before: done rc=0 3s | peak-RSS 0.92GiB | min-avail 22188MiB | peak-load 5.11
after:  done rc=0 2s | peak-RSS 0.49GiB | min-avail 22247MiB | peak-load 4.93
```

Profiles use `perf record -e cycles`; kernel symbols are unavailable on this
host. These are symbol self costs, not a complete per-stage accounting.
Disassembly of the local-statistics loop contains packed f64 `vmulpd` and
`vaddpd` instructions.

Exact libm logarithms, covariance accumulation, eigendecomposition and
raster pooling remain. Approximate logs and reassociated box sums could alter
low-variance masks or numerical parity; this change does not introduce them.
Pyramid planes and the two VIFp term maps remain allocated. NEON and wasm
variants compile from the shared macro bodies but were not executed here.

## Verification and reproduction

Default and `parallel` tests pass, including unchanged Octave goldens.
Release `parallel,_dev,avx512` tests pass (including existing VIFp tier parity).
New correlation tests compare every output bit against direct reflected taps;
new local-statistics tests compare every output bit against scalar windows.
Clippy with all targets and `parallel,_dev,avx512`, denying warnings, and
crate-scoped rustfmt pass. The shared quality kit is unavailable on this host.

Root `cargo build --locked` cannot resolve unchanged against the current
sibling checkouts. Measurements and tests therefore used an isolated workspace
containing the unchanged crate manifest, copied source, matching workspace
metadata and release profile, and the root's archmage/magetypes git pin
`72910a29`. Resolved libm 0.2.16 and rayon 1.12.0 match the root lock.
The repository Cargo.lock was not edited.

Recipes live in [the crate justfile](../justfile). Set `VIF_MANIFEST` to the
isolated or pinned workspace manifest when needed. Build examples, save their
binaries, then run `matrix <baseline-bin-dir> <optimized-bin-dir> <output-dir>`.
`profile` records cycles; `memory` runs `/usr/bin/time -v`; `verify` runs tests.

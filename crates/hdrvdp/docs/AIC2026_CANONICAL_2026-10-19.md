# AIC2026 canonical configuration research

The published HDR_VDP_2 and HDR_VDP_3 configurations remain unidentified
at six-decimal precision. This research changes no metric implementation,
default, public API or numerical gate.

[Data provenance](../../../benchmarks/hdrvdp_canonical_2026-10-19/PROVENANCE.md)
binds all 122 crop PNGs to the original dataset. The [upstream evidence](../../../benchmarks/hdrvdp_canonical_2026-10-19/UPSTREAM.md)
records official release hashes and written configuration statements.

The [AIC-4 CTC v2.0](http://ds.jpeg.org/documents/jpegaic/wg1n101246-108-ICQ-Common_Test_Conditions_on_Objective_Quality_Assessment_v2_0.pdf)
specifies HDR-VDP-2.2.2, 37.84 ppd and **203 cd/m²** for SDR; HDR-VDP-3
uses the same configuration. It names Q rather than Q_JOD. It does not
specify the complete conversion or runnable call. The AIC2026 paper's
200-nit `standard_fhd` statement is explicitly about CVVDP. Neither is
proof of the AIC2026 HDR-VDP invocation.

The upstream 3.0.7 61-pair control uses 200·sRGB_EOTF after rounding
normalized codes to 10 bits, a seven-decimal sRGB D65 XYZ matrix, OLED
emission, 37.842505866 ppd, quality, age24 and no surround. Its raw Q
residual versus the published column has median 0.0013692098323083712,
maximum 0.012360806855934214; site-JND median is
0.0013356867286653529, maximum 0.012807267024098623. **0/61** match the
published printed values. Upstream versus retained Rust differs by median
7.993605777301127e-15 Q and maximum 4.973799150320701e-14 Q. A fresh
source-identical Rust replay exactly matches the retained Rust Q values.
Thus this column residual is present in upstream; a port arithmetic change
is not supported by this control.

The retained modified Octave 2.2.2 200-nit/unrounded BT.709 baseline
replays exactly on 61/61 Q values. Its published-column residual is median
0.026509192464118314 Q, maximum 0.2199231820782117 Q. The five-file
compatibility diff adds diagnostics, removes unsupported symmetric-IFFT
arguments and forces return-value pyramid reconstruction. Reconstruction
occurs after the Q accumulator. An independent compiled-pyramid control
is recorded with the [research results](../../../benchmarks/hdrvdp_canonical_2026-10-19/README.md):
on all 61 pairs, MEX versus fallback differs by median
2.1316282072803006e-14 Q and maximum 1.4921397450962104e-13 Q.
The pyramid fallback does not explain the column gap.
The adapted Octave route must be distinguished from an actual MATLAB run.

The retained HDR3 residual occurs both in category3 crops and category1/2
images, and with/without an sRGB PNG chunk. All pixels are 8-bit RGB; no
ICC, gAMA or cHRM chunk exists in this panel. Six-pair configuration screens
are diagnostic exclusions, never complete reproduction qualifications.
Every numerical trial retains its source/driver hash and command. No
fitted correction or threshold change is part of this work.

The 3.0.6 versus 3.0.7 six-pair control differs by median
8.837375276016246e-14 Q and maximum 1.2168044349891716e-13 Q.
This is a sampled version control, not full-panel version parity. No MATLAB
executable was found in the checked local/dev locations. MATLAB's
[symmetric IFFT semantics](https://www.mathworks.com/help/matlab/ref/ifft2.html)
are distinct from merely taking the real part; the Octave adaptations do
not qualify that runtime identity.

The subsequent [symmetric-IFFT control](../../../benchmarks/hdrvdp_canonical_2026-10-19/SYMMETRIC_IFFT.md)
tests explicit Hermitian completion along both storage axes and distinguishes
that diagnostic from verified MATLAB execution. It also records independently
testable stage controls and the remaining runtime/invocation blockers.

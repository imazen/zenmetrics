# High-depth SDR decode audit — 2026-09-23

## Defect and proposed correction

The zenmetrics buffered AVIF route reads `ImageInfo.transfer_characteristics` for the PQ/HLG refusal but passes an `Unknown` transfer descriptor into `pixel_buffer_to_rgb8`. The signalled sRGB value 13 is therefore lost. The patch tags sRGB when primaries are BT.709, using the exact integer depth reduction already present on zenpixels main. Other accepted SDR transfer signals retain code-value behavior, because tagging them could cause a real transfer or gamut conversion. The question for review is whether an SDR AVIF signalled BT.709 should eventually be converted to sRGB.

## Funnel inventory

| Format | Native ingress and transfer tag | Narrowing |
|---|---|---|
| PNG16 | `zenpng::decode`; sRGB by default, cICP may replace transfer | `pixel_buffer_to_rgb8` → `RowConverter` |
| JXL16/f32 | `zenjxl::decode` native output; sRGB for integer, linear for f32 by default, metadata may replace | same funnel |
| TIFF16/f32 | `zentiff::decode`; sRGB for integer, linear for f32 | same funnel, behind `tiff` feature |
| AVIF10/12 | `ManagedAvifDecoder::decode_full`; Unknown before this patch, sRGB tagged only for nclx 13 + primaries 1 | same funnel |
| HEIC | No separate HEIC decode arm in `decode.rs`; extension currently chooses AVIF sniff fallback | AVIF path or refusal |
| sweep/jobexec SDR | Call `decode_image_to_rgb8` / `decode_rgb8_from_bytes` | same `decode.rs` funnel |
| sweep/jobexec HDR | `decode_to_nits` | Separate native HDR path |

## Validation

The logged `sdr_cicp_tag_and_native_sample_rounding` run passed all seven SDR transfer variants with zero native-sample rounding errors, but `ref_64.avif` is **8-bit**. The separate 423-byte `mono_gradient_10b_full.avif` fixture, generated by zenavif-serialize's `make_mono_avif` tool, exercises a real 10-bit AVIF. `decode_full` reported 10-bit/U16 ingress, and the RGB8 funnel had zero errors against its native samples. Because that vector has no `colr` box, the follow-up test also stamps an sRGB descriptor on its decoded buffer and asserts tagged RGB8 equals the untagged route byte for byte; the separate `ref_64.avif` test proves CICP 13 reaches that descriptor. Encoder-generated PNG16, JXL16 and TIFF16 fixtures measured 81, 121 and 239 bytes respectively; each passed exact native-code rounding. The unmodified five-test AVIF HDR tripwire and complete `cargo test -p zenmetrics-cli --release --no-fail-fast` passed again after the tagged 10-bit assertion (`8cb39caf` after rebase). Those local runs used a dirty sibling zenavif checkout, so CI against its pinned sibling is authoritative. `cargo clippy -p zenmetrics-cli --all-targets` passed with existing warnings; adding `-D warnings` fails in unrelated `iwssim-gpu` and `cvvdp-gpu` code. No existing test expectations changed. The patch now pins both zenpixels crates to main commit `e56f626b`, which already has the exact integer fix; it is temporary until `zenpixels-convert >= 0.2.17` publishes, then the minimum should be bumped and the patch dropped. This PR is independent of the separate zenpixels transfer-LUT PR.

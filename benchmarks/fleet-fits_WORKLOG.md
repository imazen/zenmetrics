### 21:35-00:48 UTC — pilot gate findings (Claude Sonnet lane)

- **Verifier/path bug (fixed, commit below).** The executor archives blob members as `fits/<cell>/...`; `harvest_fit_cells.py` / `verify_fit_gate.py` expected `<cell>/...` and failed with `unsafe or out-of-cell blob member`. Fixed in the verifier (`cell_dir()` / `BLOB_ROOT`), not the executor, so `program_sha` and job IDs stayed unchanged.
- **Checkpoint criterion (fixed).** `zensim_mlp_train` appends a JSON metadata trailer to every `.bin` (hostname = container id, `timestamp_epoch`, cwd, resolved input paths). Whole-file checkpoint hashes therefore differ per run by design. `verify_fit_gate.py` now compares the weight bytes before the trailer (`weights_sha`) and reports the full-file hash separately. Verified: for all 17 `.bin` files of a cell, tower vs r3500 weight prefixes are byte-identical.
- **v1 (static musl image, `fit-p0-v1`) result:** tower (Zen+, 24-cpu cap) and r3500 (Zen2) are **bit-identical to each other** on prediction, score, selected epoch, inner series and checkpoint weights (2 cells), and **both differ from the dev-box originals** (o0_r0: SROCC 0.9466 vs 0.9504, selected epoch 20 vs 25). Verifier output: `/var/tmp/fleet-fits/v1-musl-gate/gate-verify.json`.
- **Cause attribution (measured).** (1) Thread count is not a factor: on r3500 the first epoch is identical for `RAYON_NUM_THREADS` 1, 4 and 8 (val geomean3 0.9587, loss 0.2646). (2) libc/binary version is not the factor: the pre-rule dev binaries (`pre_current_main_binaries`, glibc) in an Ubuntu 26.04 image reproduce the fleet numbers on r3500 (0.9587) but reproduce the dev original **exactly** on the dev box (0.9578, same loss/fit/inner columns as `POT_kadid_train_r0_mlp32/o0_r0/inner0/train.log` line 13). Same binary, same image, same inputs, same flags: the only variable is the CPU. The dev box has AVX-512 and the fleet boxes do not; `zensim-train-core/src/simd_encoder.rs` has 16-wide `X64V4Token` and 8-wide `X64V3Token` dot-product kernels, i.e. different summation order. `RUST_STD_DETECT_UNSTABLE` (avx512f masked) did **not** change the dev-box result, so a tier cannot be forced from the environment; it would need a code-level switch in zensim, which is outside this lane.

Prior run: `cpu_metrics_1t8t_2026-10-09.md` on r7900x (Zen4) — cross-host deltas noted below.

Host: i265, Core Ultra 7 265K (Arrow Lake), cpus 0-7 = P-cores @5.5GHz,
8-19 = E-cores. `taskset 0-7`/`taskset -c 2` hit P-cores correctly.
Toolchain: rustc 1.99.0, zenbench, release, no target-cpu=native.

## What's left (ms/MP-ranked, 8t)

1. **mdctpsnr 657** — still top per-MP after env-hoist + AAN-FMA
   (13,845→5,546). Next: batch8 the residual serial ring/DCT stream.
2. **mad 686** — batch8'd Bluestein landed post-sweep (`28144f17`);
   next: the chirp/bf gather+scatter loops are still scalar per-lane.
3. **ssim2 96** — whole-image path in fast-ssim2 is serial (rayon only in
   approximate strip mode). Whole-image parallelization is a fast-ssim2
   PR, not an edge flip.
4. **msssim-libvmaf 85, vmaf (refuses odd dims)** — external per-frame
   impls.
5. **vif 81** — SDSP path 1.36×; deeper wins need the f64 vector story.
6. **iwssim avx512** — last feature gap: needs `F64x4Backend` for
   X64V4Token in magetypes + `infow_map_into_v4` (P1; archmage has other
   live lanes — do in a fresh window).

## Caveats

- Cross-host: Oct-9 ran on r7900x (Zen4 SMT). Scalar-f64 metrics look
  ~10-25% slower per-thread on i265 — don't read 1t deltas < ~1.3× as
  regressions. The Oct-9 doc's own caveat: ±2× leg-to-leg noise from
  interleaved groups; today's legs were serialized.
- ssim/vifvec/mad rows re-measured post-build (binary predates those
  commits — provenance in run.meta). Everything else from the single
  pinned run.
- vifvec 1t regressed ~21% (2,801→3,397) — the striped-covariance setup
  cost survives on the serial path; still +3.7× net at 8t.
- vmaf refuses odd width 3355 (needs even dims — unchanged behavior).
- Scores verified identical between 1t/8t legs for every metric.
